Project Spec — VeryBerryLab

1. Product Requirements

1.1 Для кого продукт
	•	Клиенты, заказывающие букеты с ягодами и модификаторами (B2C).
	•	Администраторы бизнеса (каталог, заказы, цены, зоны доставки).
	•	Операторы (обработка заказов).

1.2 Какую проблему решает
	•	Удобный заказ кастомных букетов с модификаторами.
	•	Централизованное управление каталогом, ценами и доставкой.
	•	Масштабируемая система для реальных пользователей (не MVP «на коленке»).

1.3 Пользовательские сценарии (UX шаги)

Клиент (iOS-приложение)
	1.	Открывает приложение.
	2.	Видит баннеры и категории.
	3.	Выбирает продукт.
	4.	Выбирает модификаторы (доп. ягоды, упаковка и т.д.).
	5.	Добавляет в корзину.
	6.	Вводит адрес / выбирает доставку или самовывоз.
	7.	Видит финальную цену.
	8.	Оплачивает.
	9.	Получает статус заказа.

Администратор (Web Admin)
	1.	Логинится в админку.
	2.	Управляет:
	•	товарами
	•	категориями
	•	группами товаров
	•	модификаторами
	•	ценами
	•	зонами доставки
	3.	Просматривает заказы.
	4.	Меняет статус заказов.
	5.	Управляет текстами приложения (FAQ, условия).

2. Engineering Requirements

2.1 Стек (ЯВНО, не менять без запроса)

	•	FastAPI
	•	SQLAlchemy 2.0
	•	Alembic
	•	PostgreSQL

Frontend (Admin)

Mobile

	•	async/await

Infrastructure

	•	Docker

	•	HTTPS (Let’s Encrypt)

⸻

3. Архитектура (компоненты и связи)

[iOS App] ---> [FastAPI Backend] ---> [PostgreSQL]
                   |
                   +--> [Admin Web App]
                   |
                   +--> [Uploads / Media]

Компоненты
	•	API — единая точка входа для iOS и Admin.
	•	Admin UI — работает через cookie-сессию.
	•	iOS App — работает через Bearer JWT.
	•	DB — PostgreSQL.
	•	Media — хранятся как файлы, в API отдаются абсолютные HTTPS URL.

⸻

4. База данных (ключевая логика)

Основные сущности
	•	Users
	•	Products
	•	Categories
	•	Product Groups (группы товаров)
	•	Modifiers
	•	Modifier Groups
	•	Orders
	•	Order Items
	•	Delivery Zones
	•	Pickup Locations
	•	Promo Codes
	•	Loyalty Settings

ВАЖНО: логика групп
	•	Группа товаров — произвольное объединение товаров.
	•	Модификаторы применяются к группе, а не к отдельному товару.
	•	Один товар может входить в несколько групп.
	•	Цена модификатора задаётся на уровне группы.

⸻


5. Инфраструктура и деплой

Локально
	•	Docker Compose
	•	Backend: localhost:8000
	•	DB: localhost:5432

Прод
	•	VPS
	•	Backend в Docker
	•	PostgreSQL в Docker
	•	Nginx проксирует:
	•	/api → backend
	•	/uploads → media
	•	HTTPS обязателен

⸻

6. Ограничения и правила для ИИ
	•	Не менять стек без явного запроса.
	•	Не добавлять лишние технологии.
	•	Не усложнять архитектуру.
	•	Любая новая логика → через существующие сущности.
	•	Всегда думать о продакшене, не «демо».

⸻

7. Цель проекта

Сделать рабочий продакшен-продукт,
которым реально пользуются клиенты и администраторы,
а не учебный пет-проект.
